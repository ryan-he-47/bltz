# ByteField 三验证结果与价值兜底(2026-09-08 调研)

> 对应《ByteField架构评估.md》§6 的三个"投稿前必查"验证项。
> 结论:**三个都能查清;价值兜底 = 新颖性核心存活,但必须正面迎战 MTPC。**

---

## 验证 1:EvaByte 的 multibyte 头 —— ✅ 你的机制新颖性存活

**查清了(代码级):** EvaByte(HKU NLP,6.5B,1.5T 字节,Apache-2.0)的 multibyte 头是:

- `lm_head = nn.Linear(hidden_size, vocab_size × 8)` —— **一个融合线性层切成 8 片,每片独立权重,全部作用在同一个 h_t 上**。head k 预测字节 t+k。
- 这是 **Medusa 式并行 MTP(独立边际)**,不是 `(h, Δ) → byte` 条件神经场。**没有 Δ 作为输入特征,8 个 offset 之间不共享任何参数,也没有 Δ 嵌入**。
- 推理是 **Medusa 树投机解码**(tree `evabyte_7b_95`,95 节点):heads 1~7 从最后一个真实位置草稿,head-0 在树注意力下验证,标准接受 + **EOS sentinel 停止**。**完全没有熵停止**。
- 无 patch 概念,字节直接进 transformer(EVA 分块线性注意力,window 2048);**无论文,仅 blog("Paper: coming soon")**。

**与你的关系:** 两个核心机制——Δ 条件单共享头、自身熵停止——在 EvaByte 里**都不存在**。EvaByte 是"字节级多字节预测"的邻居,但机制上是远邻。你的 literature §6a 的"空白地带"判断,**在头机制这一层仍然成立**。

## 验证 2:MTPC —— ⚠️ 真正的近邻,但"威胁与背书并存"

**查清了:** MTPC = *Fast and Expressive Multi-Byte Prediction with Probabilistic Circuits*(arXiv:2511.11346,v2 2026-06-02,ICML 2026,code github.com/april-tools/mtpc)。

**机制:** 概率电路(PC)在冻结的字节级骨干上表达 n 个未来字节的**联合**分布。四个家族:
- **FF = fully-factorized = 独立边际 = 你的头**(也是 Medusa/Gloeckle/EvaByte 的 MTP)。
- CP / HMM / BTree = 表达联合分布的电路。unembedding 张量 `W ∈ R^{n×r×v×d}`(n=窗口,r=秩/子节点):CP n=16 r=32 时头参数 671M,而 FF 只有 21M。

**三个与你直接相关的要点:**

1. **他们正式命名了你的失败模式。** 全文的动机示例 "Cretoria"(Cape Town vs Pretoria):独立边际可以**每个字节都自信、但联合起来不一致**。这正是你的 R1/cags 风险的理论化表述。**这是你必须正面引用并回应的一篇**——审稿人十有八九会拿它问你。
2. **但他们自己的数据反而替你辩护。** 关键发现:"**for greedy decoding FF achieves higher throughput than more expressive circuits**"(greedy 只需要 argmax 对,不需要逼近全分布);联合分布的优势集中在 **sampling** 场景。你的设计是**词内确定性 / 低熵边际解码 + 熵停止**,恰好落在"边际近似最可辩护"的 regime。
3. **他们的 future work 就是你的设计。** 附录 G 为了控制 671M 的头参数,明列了"**unembedding parameter sharing / low-rank unembeddings / hierarchical partitioning**"作为未来方向——**你的单个 `(h, Δ)` 共享头正是这一族里最便宜的实例。**

**关键区隔(要写进论文):**
| | MTPC | ByteField |
|---|---|---|
| 定位 | 冻结预训练字节 LM 上的 **retrofit 投机草稿头** | **从零训练**的字节 LM 主生成器 |
| 验证 | **永远有 verifier**(投机解码,质量保证) | **无 verifier**,熵停止即本地拒绝 |
| 停止 | 固定窗口 n=8/16,EOS 限制 | **自身熵自适应变长停止** |
| 依赖 | 需预训练字节骨干 | 不依赖任何预训练模型 |
| BLT/Fast BLT | **完全没碰**(BLT 仅在 intro 一句带过) | 正面继承并区隔 |

**净结论:** MTPC 没有占据你的位置——"**从零训练 + 无 verifier + 熵自停止 + 语义 patch 完备性辩护**"这个组合仍然是空的。但 MTPC 是唯一一篇把"独立边际是 bug"讲成正式论点的工作,你的 intro 必须从它写起(先承认 FF 的局限,再论证为什么语义 patch + 熵停止 + greedy regime 让你的 FF 变体站得住)。

## 验证 3:BLT 式 124M 对照臂 —— ✅ 可行,但有一条血泪史要吸收

**查清了:**

1. **官方配置完全组件化,缩放无门槛。** `facebookresearch/blt` 的 `blt.py` 里 `ByteLatentTransformerArgs` 把 `dim_global / dim_local_encoder / dim_local_decoder / n_layers_* / cross_attn_k / hash vocab 大小` 全部做成 yaml 可配。官方最小 "400M" 的组件比(Table 10):**编码器 7M(1 层)/ 全局 470M(24 层)/ 解码器 50M(7 层)+ hash 表**。缩放成 124M = 调数字即可。
2. **小尺度有正面先例:**
   - `sssssaud/blt-llm`:55.4M + 1.7M 熵模型,TinyStories 2.2B 字节,20k 步,**最佳 0.7078 BPB**,RTX 3050 6GB 约 2.4h。(repo 已删,HF 卡片留存,正面数据点)
   - `laerdon/blt-replication`:~86M,FineWeb-Edu 1.7B 字节,BLT vs GPT-2 同预算对照,仓库含结果图。(正面,更接近你的设定)
3. **小尺度有血泪史(务必吸收):**
   - `ianbarber/ttblt`:Qwen-2.5-3B 当全局 + **仅 150M 字节** SlimOrca → 教师强制 1.7-2.2 BPB 尚可,但**自回归生成语无伦次**。作者归因于**数据规模:局部编码器/解码器必须从零学习 byte↔patch 映射,36.3 万样本远远不够**。还修了一串 bug(loss mask、decoder cross-attn 泄漏、batch 依赖的 patching 等)。
   - facebookresearch/blt issue #128:社区 0.8B 配置跑 fineweb-edu-10bt,val BPB 卡在 1.4-1.8(停滞)。
   - **教训:BLT 的数据饥渴部位正是局部编码器+解码器。** 你的架构的数据饥渴部位也恰好是 Set Transformer 编码器 + 条件头——所以这条血泪史对你同样适用,而且是好事:它告诉你在哪一层预先埋诊断。
4. **算力估算:** 小尺度 BLT 实测达成 ~6 TFLOPS(sssssaud 的 3050、ttblt 的 GB10 都是这个量级)。124M 跑 10B 字节 ≈ 6×124M×10B×~1.3 开销 ≈ **7e18 FLOPs**,RTX 4060 达成 30-60 TF 时 ≈ **理想 1.5-4 天,现实 1-3 周**(含 checkpoint/调参)。**可行。**

## 价值兜底:一句话版

> **新颖性核心存活,但叙事必须从 MTPC 写起。** EvaByte 证明"字节级多字节预测"有人做过(但机制是 Medusa 式、带 verifier、无熵停止);MTPC 证明"独立边际"的局限被正式命名了(但他们的数据反而证明 greedy regime 下边际够用,且他们的 future work 就是你的共享头)。**从零训练 + 无 verifier + Δ 条件单头 + 自身熵停止 + 语义 patch 完备性辩护——这个组合,截至 2026-09-08,无人占据。** BLT 式 124M 对照臂可行,且小尺度 BLT 的先例已证明"数据足够时能成",血泪史证明"数据不够时先死的部位"。

**论文必须补的一节:** "Related work" 里把 EvaByte(字节级 multibyte,但 Medusa 式+验证)、MTPC(独立边际的局限 + joint circuit,retrofit+验证)并排放,然后明确你的差异化主张:在**语义完备 patch + 词内确定性 + greedy/低熵 regime**下,独立边际的自停解码是一个可证伪的、且被 MTPC 自己数据部分支持的设计点——而不是忽略独立边际的已知局限。
