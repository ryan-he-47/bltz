## 1. 工作定位

1. **长板主张**:"只要模型的长板——vocab free 的泛化性和推理效率——能 work 有效果,其它的窟窿都能看作 trade off。"
2. **创新姿态**:不追求颠覆式创新。"我也不好说我这是不是真创新,毕竟方法是组合式的,目的是复古的。"
3. **风险态度**:评审中识别出的高风险设计**一律不改**,因为它们是实验本体:"这些坑正式构成我架构主张的、直接挑战 blt 的实验项。""虽然直接挑战一个顶会 best paper 大概率是以失败收场,但是求稳算鸡毛科研。"
4. **工程价值观**:落地优先,允许缝补。"落地效果好不一定非得模型素质非常过硬,大把的 engineering trick 可以用,缝缝补补也能把短板遮个大差不差。""能便宜解决的问题就先不考虑贵办法。"

## 2. 学术生态位

1. **自我定位**:"学院派 llm 和语言表征维新派之间的**和事佬**"——既想要 byte level 的分辨率来解决词表繁重不可扩展的问题,又不想离开 token lm 的成功范式走太远。
2. **相对 BLT 的立场**:"我和 blt 站在不同的问题视角上。blt 直接抛弃词表先验,面向长度不确定、边界不确定的 byte 流切成的 patch 设计全新的架构;我的思想保守且折中一点。"
3. **架构的本质描述**:"把 llm 的分词器算法拿来打包 patch,拿一个小 encoder 来把这些 token-ish patch 编成向量,骨干在这些向量上做自回归,然后用一个解码器把这些 token-ish 嵌入向量解回一小段 byte 组成的语义单元。这实际上更像是一个传统的 token level lm,只不过是借助 set transformer 和条件解码头看到了 byte level 的分辨率。"
4. **一句话总结**:"把一个定死的大嵌入矩阵变成了一套**可学习、可泛化、更易微调的嵌入向量 i/o**,算是面向传统 lm 的**新瓶装旧酒**,而不是颠覆性的创新。"
5. **自我调侃**:"造出来这么一坨在 byte lm 圈里一股怪味的设计。"——用户清楚此定位在字节级 LM 圈内非主流,并接受这一点。

## 3. 设计哲学(逐条,含出处辩护)

### 3.1 设计公理(已记录于 01-design.md §1 的"用户原话",此处仅为完整性引用)

> "我们的架构如果非要依赖一个很高效很精准的分词算法才 work 的话,那就已经失败了。"

分割器是给架构减负的先验,不是架构的拐杖。

### 3.2 纯并行解码(条件解码头,无字节回喂)的出处辩护

- 出处:"直接继承自 medusa 的 mtp 思想。"
- 论证:"如果每两个 token 间都有复杂因果性的并行 mtp 都能 work,那在这个**只有边界存在复杂因果性**的 byte level mtp 上,任务难度更简单,它没道理直接血崩了。"
- 设计语义:字节流的复杂因果性集中在 patch 边界(词界);词内字节近乎确定,因此并行边际解码的风险显著低于 token 级 MTP。

### 3.3 局部编码器(patch 局部视野)的出处辩护

- 立场:不是照搬 BLT,而是向标准 token LM 回归。"我背离 blt 的所有设计——把长上下文的语义功能全部赶回骨干、给输入划清晰的语义边界、让骨干输出不显式照顾 byte level 分辨率——实际上都是在向标准的 token lm 回归。"
- 对比:BLT 是面向"长度不确定、边界不确定的 byte 流"的激进派;本项目是保守折中派,复用 token LM 的成熟范式与分割先验。

### 3.4 纯并行稳定性的工程兜底(不依赖模型自身素质)

- 现成算法纠错:"手机输入法早有了错字纠错功能,word 文档也有 typo 识别,模型跑推理的时候套上一个现成算法做纠错就行,只要不是纯胡言乱语,应该都能纠正的大差不差。"
- 深度学习式兜底:"检查到 typo 之后直接把错词挖掉,然后请一个小 bert 来把空位补上。"
- 原则:"不一定什么都要依赖模型本身的稳定性,能便宜解决的问题就先不考虑贵办法。"
