## 2. 效率观察

1. **inducing=16 = l_max**:ISAB 的压缩瓶颈宽度 = 输入宽度,归纳偏置失效
   (用户首先指出)。诱导向量本身仅 8K 参数,省不了参数,但砍到 4/2 能
   **强迫真压缩**;真正的冗余在 2 个 ISAB 本体(12.6M)。
2. **头/骨干的算力-参数不对称**:Head 6.3% 参数吃 ~60% per-patch FLOPs
   (341M vs 226M,docs/06)——参数效率最高,勿动;骨干 81.8% 是容量主体,
   为与 190M token 基线可比,精调建议也先不动。
3. **Encoder 功能现状**(60k 证据):字符级压缩器,无语义信号,位置部分使用。
   2 层 ISAB(d=512)+ PMA 对 ≤16 字节的 patch 大概率超配。
4. PMA(k=1)一个 MAB 花 3.15M 做池化,与一层 ISAB 同价——池化是否真的
   需要完整 MAB,存疑(可试 mean-pool 消融,D8 本来就留了这个消融臂)。

## 3. 精调旋钮清单(节省估算;均未拍板)

| 旋钮 | 现状 → 候选 | 参数变化 | 备注 |
|---|---|---|---|
| inducing | 16 → 4/2 | ~0 | 强迫压缩;配合其它砍法 |
| enc_layers | 2 → 1 | **-6.31M** | ≤16B patch 单层大概率够 |
| d_enc | 512 → 384 | -3~-4M | 与层数砍可叠加 |
| PMA → mean-pool | MAB → mean | -3.15M | D8 消融臂本来就留着 |
| byte_emb+pos_emb | 384+64 → 256+32 | ~-0.1M | 毛毛雨 |
| head | 不动 | 0 | 参数效率最高,FLOPs 主力 |
| backbone | 暂不动 | 0 | 与 token 基线可比性优先 |

**Encoder 极限压缩参考**:d_enc=384 + 1×ISAB + inducing=4 + mean-pool
≈ **4-5M**(从 16.5M),腾出的 ~11M 可补骨干或留着做更小对照模型。
